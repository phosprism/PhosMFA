# PhosMFA

Discord認証で保護された共有TOTP認証コード管理アプリです。Cloudflare Workers上で動作し、Cloudflare D1に保存したTOTPシードを使って、複数人で共有アカウントの2段階認証コードを確認できます。

## リポジトリの内容

- `worker/`  
  Cloudflare Workersのサーバー処理です。Discord OAuth、アクセス制御、D1からのデータ取得、TOTPシードの暗号化・復号を担当します。

- `index.html`, `app.js`, `styles.css`  
  ブラウザで動くフロントエンドです。認証コードの表示、コピー、QRコード読み取り、PWA、オフライン表示を担当します。

- `src/`  
  ブラウザ向けにバンドルする補助コードです。QRコード読み取りやAuthenticator関連のライブラリをまとめています。

- `scripts/`  
  Cloudflareへデプロイするために、必要な静的ファイルを`public/`へコピーする準備スクリプトです。

- `schema.d1.sql`  
  Cloudflare D1を新しく作るときのテーブル定義です。

- `migrations/`  
  既存のD1に順番に適用する変更です。`0001` から番号順に `wrangler d1 execute --remote --file` で適用します。

- `manifest.webmanifest`, `sw.js`, `icons/`  
  PWA対応に必要なmanifest、Service Worker、アプリアイコンです。

- `wrangler.example.toml`  
  Cloudflare Workers用の設定テンプレートです。本番用の`wrangler.toml`は公開しない想定です。

## アプリのフロー

1. ユーザーがページを開く

2. Workerが署名付きCookieのセッションを確認する

3. 未ログインの場合はDiscordログイン画面へ誘導する

4. Discord OAuthでユーザー情報と参加サーバー情報を取得する

5. 指定されたDiscordサーバーに参加しているか確認する

6. `DISCORD_ALLOWED_USER_IDS` が設定されている場合、そのユーザーIDリストに含まれているか確認する

7. 認証に成功したら、署名付きCookieでセッションを保持する（この時点では2段階認証は未完了）

8. 2段階認証を登録していない場合は、パスコード（4桁か6桁・必須）とパスキー（任意・推奨）を登録し、「開いたときにもロックするか」を選ぶ

9. 登録済みの場合は、パスキーかパスコードで本人確認をする。5回続けて失敗するとアカウントをロックし、管理者が解除するまで使えない

10. 「開いたときにもロックする」を選んだ人は、ページやPWAを開くたびに本人確認をする。確認が済んだことを示すトークンは、ページのメモリにだけ置く

11. ページ表示時、フロントエンドはまず`/api/me`を呼び出して現在のセッションを確認する

12. Workerは`/api/me`や各APIアクセスのたびに、現在のユーザーがallowlistに残っているか再確認する

13. allowlistから外されたユーザーがアクセスした場合、WorkerはセッションCookieを削除して401を返す

14. フロントエンドは401/403を受け取ると、ブラウザ内のオフライン用キャッシュを削除してログイン画面へ戻す

15. allowlist拒否やオンライン中の認証失敗では、PWAのオフラインモードへは切り替えない

16. 認証済みユーザーは`/api/accounts`から登録済みアカウント情報を取得する

17. WorkerはD1から暗号化済みTOTPシードを読み出し、AES-GCMで復号する

18. ブラウザ側でTOTPコードを30秒ごとに生成・更新して表示する

19. Workerから返されたサーバー時刻を使い、ブラウザ時刻との差分を補正してTOTP更新タイミングを合わせる

20. オンライン時に取得したアカウント情報とPWA用ファイルをブラウザに保存する

21. ブラウザが本当にオフラインの場合のみ、保存済みデータからPWAのオフラインモードを起動する

22. オフラインモードでは、保存済みTOTPシードからブラウザ内で認証コードを生成する

23. 管理者として許可されたDiscordユーザーだけが、QRコードやシード入力から新しい認証情報を追加・削除できる

24. 管理者は、トップページの「パスワード管理」から、チームで共有するIDとパスワードを登録・編集・削除できる（テスト中のため管理者だけ）

## セキュリティ方針

- TOTPシードはD1に保存する前にAES-GCMで暗号化します。
- セッションは署名付きCookieで管理します。
- Discordログインに加えて、パスコードかパスキーによる2段階認証を必須にしています。Discordアカウントが乗っ取られても、それだけではシードを取得できません。
- パスコードはサーバーの秘密鍵を混ぜたHMACで保存し、5回続けて失敗するとアカウントをロックします。
- パスキー（WebAuthn）は本人確認（指紋・顔認証など）を必須にし、署名・チャレンジ・オリジンをWorker側で検証します。
- 管理者（`DISCORD_SECRET_MANAGER_USER_IDS`）は「利用者の管理」から、ロック解除・2段階認証のリセット・ロックと強制ログアウト・ログイン履歴の確認ができます。
- 管理者は、アカウントの並び順と、利用者ごとに表示するアカウントを決められます。非表示にしたアカウントのシードは、その利用者にはサーバーから送りません。
- 「開いたときにもロックする」を選んだ人のオフライン用キャッシュは、パスコードを知らないと開けない形で保存します。オフラインで5回間違えると端末内のデータを消去します。
- パスワード管理のIDとパスワードは、チームで共有するマスターパスワードからPBKDF2-SHA256（60万回）で作った鍵で、ブラウザの中でAES-256-GCMで暗号化してから保存します。サーバーとD1には暗号化したデータしか置かないので、サーバーの秘密鍵が漏れても中身は読めません。マスターパスワードを忘れると、誰も中身を読めなくなります。
- アクセス時にallowlistを再確認し、外されたユーザーは即ログアウトさせます。
- allowlist拒否時はPWAのオフラインキャッシュも削除します。
- `.env`、`wrangler.toml`、`.wrangler/`、`public/`、`dist/`はGitHubに含めない運用です。
- オフライン利用のため、認証済みブラウザにはTOTPシードが暗号化して保存されます。共有端末ではログアウトしてキャッシュを削除する想定です。

## 管理者が全員ロックされたとき

管理画面に入れる人がいなくなった場合は、Cloudflare D1を直接更新して解除します。

```bash
npx wrangler d1 execute <DB名> --remote --command "UPDATE app_users SET locked_at = NULL, lock_reason = NULL, failed_attempts = 0 WHERE discord_id = '<DiscordユーザーID>'"
```
